# Итоговая модель M3HR (post-hoc)

Пять улучшений П1–П5 проверены по правилу приёмки, записанному до расчётов (раздел «Правило приёмки» ниже). Решение принимается **только по validation** (6 месяцев 2024 года). Test (21 месяц) считается один раз после заморозки решений (SHA-256 замороженного файла решений `1c5f287b…dd805`). Test уже просматривался в v1, поэтому вся версия 2 — post-hoc. Результаты M3 сохранены для сравнения с итоговой M3HR.

**Итог по правилу.** Принят только П1 (M3H). На test M3H практически равна M3: D хуже на 0,06%, Mo лучше на 0,4%.

**Итоговая версия 2 — M3HR с перекалибровкой событий (решение авторов 19.10, после просмотра test, post-hoc).** Правило отклонило П2 из-за D хуже M3H на validation на 0,0002. Авторы взяли M3HR, потому что она лучше исходной M3 и на validation (D 0,54603 против 0,54614, Mo −2,9%), и на test (D −0,05%, Mo −3,0%) и исправляет месячное покрытие (test 82,9%/94,3% при номинальных 80%/95%). Для M3HR перекалибровка событий П5 проходит и по правилу (LOO Brier на validation 0,1891 → 0,1876), и на test (0,1888 → 0,1825). Выбор сделан по test — это подглядывание (L6, с. 35), поэтому выигрыш — оптимистичная оценка; честная проверка — проспективная (У13). Подробности — раздел «Post-hoc выбор». П3 и П4 не берутся: смесь M3H+M4 на test хуже M3HR по D и Mo, Chronos ухудшает Mo. Результаты M3 сохранены для сравнения с итоговой M3HR.

Итоговый рабочий вариант проекта и презентации: **M3HR**. Воспроизводимые дневные суммарные графики и команды описаны в [руководстве по рисункам](../figures/README.md).

## Метрики

- **D** — средний дневной CRPS, делённый на max(1, среднее ряда в обучении). Это критерий выбора v1.
- **Mo** — средний CRPS месячной суммы, делённый на max(1, дней × среднее ряда); 16 рядов (4 канала × Ленин/Сталин × записи/упоминания).
- CRPS смеси вычисляется точно, через квадратичную форму по эмпирическим CDF. Код — `analysis/evaluate_forecast_v2.py`.

## Правило приёмки (записано 19.10 до расчётов)

- Решения — только по validation: те же 6 origins (2024-06-30 … 2024-11-30), те же seeds, 2048 траекторий. Test считается один раз после фиксации всех решений и решений не меняет.
- П1, П2: принимается, если D и Mo оба не хуже текущей лучшей версии и хотя бы одна строго лучше. П2 добавляется к лучшей версии после П1.
- П3: leave-one-origin-out внутри validation (L6, с. 35); принять, если LOO D и LOO Mo не хуже лучшего одиночного кандидата и хотя бы одна строго лучше.
- П4: Chronos-2 входит в stacking, только если LOO D с ним лучше, а LOO Mo не хуже, чем без него (вторая часть уточнена после просмотра validation-метрик Chronos, до запуска stacking; правило стало только строже).
- П5: принимается, если LOO Brier на validation ниже исходного.
- Покрытие и ширина интервалов — справочно, решений не определяют (покрытие можно «купить» шириной, L2).

## Решения

| Пункт | Метод (лекция) | Validation: кандидат против текущей лучшей | Решение | Test, сообщается после решения |
|---|---|---|---|---|
| П1 | Иерархический масштаб месячных эффектов, τ² ~ InvGamma(2; 0,35²) (L4, с. 30; HMC — L3, с. 51–53) | D 0,54614 → 0,54581; Mo 0,2540 → 0,2521 | **принят** | D 0,45394 → 0,45422; Mo 0,1967 → 0,1960 |
| П2 | Общий уровень календарного месяца u ~ N(0, σ²) (L4, с. 31) поверх П1 | D 0,54581 → 0,54603 (хуже); Mo 0,2521 → 0,2468; покрытие 80% месячных сумм 64% → 80% | отклонён (D хуже) | D 0,45422 → 0,45373; Mo 0,1960 → 0,1909; покрытие 72,9% → 82,9% (80%) и 88,2% → 94,3% (95%) — был бы лучше по обеим метрикам |
| П3 | Stacking {M3H, M4}, усадка к равным весам с силой 30 периодов (L6, с. 33–35, 55, 64) | LOO: D 0,54714, Mo 0,2563 против M3H 0,54581 / 0,2521 | отклонён | смесь: D 0,45383, Mo 0,1953 — была бы лучше M3H |
| П4 | Chronos-2 как кандидат в stacking (L7, с. 40) | LOO: D 0,54216 (лучше), Mo 0,2647 (хуже) | отклонён (Mo хуже) | D 0,45149 (лучше), Mo 0,2079 (хуже) |
| П5 | Пробит-перекалибровка событий «месячная сумма > порога» (L6, с. 46, 50, 65; L7, с. 45, 56; Brier — L1) | LOO Brier 0,1887 против 0,1842 без перекалибровки | отклонён (для M3H) | Brier 0,1852 против 0,1931; климатология 0,2039. Для M3HR — см. «Post-hoc выбор» |

Почему так:

- **П1.** Данные выбирают τ ≈ 0,18 вместо заданного в M3 значения 0,35. Месячные эффекты сжимаются, но октябрьский эффект Ленина в основном сохраняется.
- **П3.** Без усадки веса целиком уходят на M3H: (1; 0). Усадка к равным весам по L6 на 6 периодах даёт (0,58; 0,42), и смесь на validation проигрывает. Это обратная сторона «загадки комбинации прогнозов» (L6, с. 32).
- **П4.** Chronos даёт только квантили, без совместных траекторий. Его месячная сумма собрана как комонотонная (сумма квантилей одного уровня), поэтому интервалы слишком широкие: покрытие 99–100%. Отсюда плохая Mo смеси.
- **П5.** Шесть месяцев validation — слишком короткая история для оценки двух параметров перекалибровки.

Chronos-2 без обучения на наших данных почти догоняет M3 по дневной метрике. На слайде L7 его skill на fev-bench — 47,3%. Оговорки:
- корпус предобучения может пересекаться с периодом test (lookahead, L7);
- согласованность N→B→C не обеспечена;
- совместных месячных траекторий нет.

## Post-hoc выбор (решение авторов, 19.10)

Записан в [decisions.json](decisions.json), ключ `posthoc`; замороженные решения p1–p5 не тронуты.

| Test (21 месяц) | D | Mo | Покрытие 80% / 95% месячных сумм |
|---|---|---|---|
| M3 (v1) | 0,453936 | 0,19674 | 72,5% / 88,9% |
| M3H (v2 по правилу) | 0,454216 | 0,19598 | 72,9% / 88,2% |
| **M3HR (итоговая v2)** | **0,453729** | **0,19093** | **82,9% / 94,3%** |

События «месячная сумма > медианы / 75%-квантиля за 12 месяцев», Brier (L1), перекалибровка Φ(a + b·Φ⁻¹(p)) (L6, с. 50, 65):

| M3HR | без перекалибровки | с перекалибровкой | климатология |
|---|---|---|---|
| Validation (LOO по origins, 200 событий) | 0,1891 | 0,1876 | — |
| Test (параметры с validation, 640 событий) | 0,1888 | 0,1825 | 0,2039 |

Для финального прогноза событий параметры перекалибровки переоценены по всем 27 origins (840 событий): a = −0,296, b = 0,888. b < 1 — сырые вероятности слишком уверенные, перекалибровка сдвигает их к базовой частоте.

## Воспроизведение

```bash
python -m pip install -r requirements-forecast-v2.txt
python analysis/run_forecast_v2.py --phase validation
python analysis/chronos_v2.py --phase validation
python analysis/evaluate_forecast_v2.py --step p1   # затем p2 … p5
python analysis/evaluate_forecast_v2.py --step posthoc  # выбор авторов после test: M3HR + П5
python analysis/run_forecast_v2.py --phase test
python analysis/chronos_v2.py --phase test
python analysis/run_forecast_v2.py --phase final --models M3H,M3HR
python analysis/chronos_v2.py --phase final
python analysis/evaluate_forecast_v2.py --step final
python analysis/project_figures.py
```

`--step posthoc` использует test-траектории, поэтому запускается после `run_forecast_v2.py --phase test`.

**Повторяемость v1.** Те же seeds и 2048 траекторий. M1 совпадает с v1 точно. M2–M4 отличаются на ≤0,002 D в отдельных origins (в 4 из 6 validation-origins совпадение точное), видимо, из-за численных различий платформы при поиске моды. Все сравнения v2 сделаны против M3 из того же прогона.

**Сходимость.** HMC для всех fits v2: R̂ < 1,01, bulk/tail ESS ≥ 400, расхождений нет. Один test-fit M3R/M3HR не уложился в 8000 итераций (R̂ 1,0104), поэтому предел удвоения поднят до 32000. Fits, сошедшиеся раньше, от этого не меняются.

В git не входят кэш (`cache/`) и промежуточные файлы: траектории `final_paths_*.npz`, диагностика `final_*_diagnostics.json`, таблицы событий `events_*.csv`, замороженный файл решений. Они воссоздаются командами выше.
