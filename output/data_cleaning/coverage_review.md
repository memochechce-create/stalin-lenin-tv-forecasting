# Исправленное покрытие ТВ

Локальный пересчёт 17.10.2026, интервал 01.01.2023–02.10.2026 включительно. Источник — `data_collection/data/tv.sqlite`, открыт строго `mode=ro`. Сетевых запросов, изменения базы и прежних экспортов нет.

## Интерфейс

`from analysis.tv_coverage import load_coverage`

`result = load_coverage(db_path, '2023-01-01', '2026-10-02', supplemental=None)`

Возвращает JSON-совместимый словарь: `daily` — полный календарь channel/MSK day; `broadcasts` — все архивные ID внутри интервала с признаками качества; `canonical_id_by_id` — отображение каждого ID в выбранный ID; `diagnostics` — сводные флаги. Используется только стандартная библиотека Python. Даты включительны; UTC timestamp считается источником времени, московские сутки вычисляются как UTC+03:00, что соответствует всему данному историческому интервалу. Необязательный `supplemental` подключает успешные записи отдельной ремонтной базы через общий `analysis.source_database.open_source_database`; обе базы доступны только для чтения. Числа ниже относятся к исходной базе без overlay.

## Правила

- Для московских суток требуются успешные перечни **предыдущих и текущих UTC-суток**. Отсутствующий перечень — `not_collected`, а не успешный пустой день. Пустой перечень передач после группировки не считается наблюдаемым днём даже при двух HTTP 200.
- В дневных строках отдельно сохранены `raw_*` и `canonical_*`: перечисленные ID, доступные тексты, недоступные тексты, число слов, суммарная длительность доступных записей и число коротких ASR. Число слов берётся из сохранённой базы; чтение HTTP 200 здесь не заменяет проверку исходных файлов.
- Канонизация касается только одинаковых channel + start_time UTC. Приоритет: успешная расшифровка, затем самая длинная запись по start/stop, больше слов, наличие названия программы, лексикографический ID. Название само по себе не перевешивает сохранённый длинный успешный фрагмент. Все ID и отображение сохраняются; реальные показы с другим временем начала остаются.
- Обычные пересечения времени только помечаются `overlapping_archive_record`, их речь и упоминания автоматически не удаляются. Флаг отражает пересечение с уже начавшейся записью, а не доказанный повтор конкретной фразы. Для проверки начала подынтервала дополнительно читаются предыдущие московские сутки; эти контекстные строки не попадают в возвращаемые знаменатели. Это единица **архивная запись**, а не уникальная секунда эфира.
- HTTP 200 с менее чем 20 словами получает `short_asr`; при длительности строго больше 10 минут — также `long_low_word_asr`, и соответствующий канонический день консервативно считается ненаблюдаемым. Это диагностическая эвристика, не доказательство сбоя ASR. Неположительная длительность, недостающий word_count и конфликт UTC/local metadata тоже исключают наблюдаемость.
- `observed` означает доступность всех перечисленных канонических текстов при успешных двух перечнях и прохождении указанных проверок качества. Оно не утверждает непрерывное вещание, точность ASR или разрешение смыслов фамилии. Малые временные пересечения сами по себе observed не выключают.
- `canonical_available_union_seconds_started_today` показывает объединение доступных интервалов, начавшихся в данных сутках, с обрезкой на границе суток. Это диагностика: передачи, начавшиеся до полуночи, в эту величину не входят. Суммарные длительности `*_available_duration_seconds` могут превышать длину суток из-за пересечений и потому не являются процентом покрытия.

## Результат

| Показатель | Значение |
|---|---:|
| Строк channel/day | 5484 |
| Исходных ID в MSK-интервале | 114895 |
| Канонических ID | 114885 |
| Групп с одинаковым началом / дополнительных ID | 10 / 10 |
| Канонических записей с пересечением | 83946 |
| Наблюдаемых дней по исправленному правилу | 5330 |
| Ненаблюдаемых дней | 154 |
| Дней с недоступным предыдущим UTC-перечнем | 114 |
| Дней с недоступным текущим UTC-перечнем | 110 |
| Дней без перечисленных записей | 114 |
| Дней с недоступными каноническими текстами | 15 |
| Дней с длительным коротким каноническим ASR | 4 |

Причины пересекаются и не суммируются. Среди всех raw ID найдено 10 коротких успешных ASR, из них 5 длиннее 10 минут. После канонизации/группировки дневной флаг затрагивает 4 дня. Ошибок разбора timestamps нет.

Начало 01.01.2023 остаётся неполным на всех четырёх каналах: перечни 31.12.2022 не были сохранены. Локальный пересчёт не восстанавливает отсутствующие записи и не превращает неполноту в нули.

Выбор самого длинного same-start фрагмента воспроизводим, но его ASR не гарантированно включает каждый распознанный токен короткого варианта. В аудите уже отмечен Lenin-кандидат в коротком `RUSSIA24_20260809_140000_Vesti`, отсутствующий в одновременной безымянной записи. Поэтому raw и canonical результаты нужны для проверки чувствительности; выбранное правило не доказывает тождество расшифровок. Точная очистка повторной речи на разных началах требует cue timestamps/проверки текстовых пересечений и остаётся отдельным слоем.

## Проверка

`python -m unittest discover -s tests -p test_tv_coverage.py`

Пять тестов прошли: UTC/MSK и необходимость двух перечней; високосный февраль/переход месяца/пустой день; выбор длинного успешного same-start варианта с детерминированной ничьей и сохранение реального повтора; HTTP 200 с длинным коротким ASR без превращения в наблюдаемый ноль; пересечение с записью из предыдущих суток без попадания её в знаменатель. После подключения общего read-only helper повторный запуск пяти тестов и полного локального прохода подтвердил те же результаты: 10 групп и 83946 пересечений.
