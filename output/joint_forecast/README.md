# Прогноз на исправленных данных

Главный визуальный результат: [forecast_report.html](forecast_report.html). Самодостаточный HTML с минималистичными SVG, переключением между двумя прогнозируемыми величинами и таблицей месячных итогов. Графики отдельно в `figures/` в форматах SVG и PNG.

Расчёт завершён 18 октября 2026. По ранней validation выбрана M3. На внешних 21 месяцах daily scaled CRPS улучшился относительно M1 на **10,18%**, RMSE — на **1,70%**. Дневные M3/M4 почти равны по точности, но **месячное покрытие M3 недостаточно: 72,1%/90,0% при номинальных 80%/95%**; M4 ближе к номиналу: 77,9%/91,8%. Эти ограничения явно показаны в отчёте. Все 290 статических component fits проходят Rhat/ESS; 22 теста и отдельный валидатор прошли, все 9 Python-ячеек ноутбука исполнены.

**Отчёт для сдачи:** [final_project.ipynb](final_project.ipynb). Пошаговые объяснения, формулы, вычисления, диагностики, результаты и связь с лекциями/семинарами L1–L6. Условия из инструкции преподавателя: объяснять каждый шаг, предоставить все вычисления и доступные данные.

## Воспроизведение

Из корня `stalin-lenin-tv-forecasting`, Python 3.12 или 3.13:

```powershell
python -m pip install -r requirements-forecast.txt
python analysis/run_joint_forecast.py --jobs 3
python -m unittest discover -s tests -v
```

Первая команда устанавливает только библиотеки прогноза. Сам расчёт работает локально: Google Cloud, Chrome, ключи и внешние API не нужны. `--jobs 1` выполняет то же последовательно. Обычный запуск переиспользует статические posterior-кэши только при совпадении исходных данных, кода модели и настроек; предсказания и оценки пересчитываются. `--rebuild` заново оценивает все posterior. Это продолжительный CPU-расчёт; результаты каждого завершённого origin сохраняются по ходу.

Команда создаёт численные результаты, проверяет их и оформляет графики, HTML и ноутбук. Для исполнения ячеек ноутбука после расчёта:

```powershell
python analysis/execute_forecast_notebook.py
```

`python analysis/package_joint_project.py` собирает `submission_bundle.zip` с ноутбуком, кодом, исправленной таблицей и результатами (без тяжёлого исходного корпуса и кэшей posterior). Архив нужно полностью распаковать перед запуском.

В ноутбуке `RUN_REBUILD=False` читает и перепроверяет готовый расчёт; `True` запускает его заново. Код модели и расчёта поставляется в `analysis/`, параметры, версии и SHA-256 — в `manifest.json`. Для проверки и оформления отдельно:

Скрипт исполнения последовательно выполняет все Python-ячейки через IPython в одном процессе и сохраняет rich outputs в обычный `.ipynb`; отдельные localhost-соединения ядра не нужны. Сам ноутбук можно также выполнять обычным способом в Jupyter.

```powershell
python analysis/verify_joint_forecast.py
python analysis/forecast_artifacts.py
```

## Объект и временная граница

Восемь сочетаний человек × канал, две цели на каждое: число упоминаний фамилии C и число архивных записей с хотя бы одним упоминанием B. Прогнозируется и знаменатель N, число доступных канонических архивных записей в полном дне. Источник: `data/cleaned/tv_daily_targets.csv.gz`.

Последнее наблюдение — **2 октября 2026**, горизонт **3 октября — 2 ноября 2026**, 31 день по заявке. Поскольку расчёт оформлен позднее границы данных, это frozen-cutoff воспроизведение: оно не использует наблюдения после 2 октября и не должно представляться как прогноз из сегодняшнего информационного набора.

День — MSK-дата начала архивной записи. Учитываются все программы, включая рекламу и повторы в другое время. Неполные дни исключены из обучения и оценки, а не заменены нулями. Это прогноз измеряемого архивного ряда при сопоставимом измерении, а не прогноз политического курса.

## Методы и соответствие заявке

Во всех моделях используется общая факторизация:

`N → B|N → C=B+E|B`.

Для каждого человека внутри записи с упоминанием моделируется положительное количество `1+X`; E — сумма дополнительных X в B записях. N общее для Ленина и Сталина; B/E условно независимы между людьми. Это гарантирует `0≤B≤N`, `C≥B`, `B=0 ⇒ C=0` на уровне каждой реализации.

1. **M1:** Gamma–Poisson N, Beta–Binomial posterior для постоянной доли p (дневной likelihood — Binomial), Gamma–Poisson для E с exposure B. Аналитическое обновление по L2.
2. **M2:** NB для N, Beta-binomial для B|N и NB для E|B с mean `B*lambda`, size `B*k`. Предусмотрена дополнительная вариация. Общий уровень и сжатые канальные контрасты внутри каждого компонента. Статический posterior оценён точным Metropolis–Hastings, L3.
3. **M3:** M2 плюс тренд, month/weekday и специальные даты. Иерархия задана Normal-приорами: общий уровень оценивается совместно с отклонениями каналов, календарные контрасты сжимаются к нулю. Гипермасштабы фиксированы, а не оценены: это prior-specified pooling, L4. Явные индикаторы 7 ноября/8 мая и других дат есть даже вне финального горизонта.
4. **M4:** M3 плюс случайные блуждания на log/logit-шкале; conditional particle filter, L5. Последние 365 дней и начальное `N(0,0.25²)` для состояния; propagate–weight–resample, ESS<P/2. Это модульное приближение (cut posterior), не полный joint Bayes. При пропуске выполняется только динамический переход.
5. **POOL:** равновесная смесь четырёх полных predictive-распределений, L6. Одна модель выбирается на целую траекторию. Никакого независимого усреднения интервалов или исправления несогласованных счётчиков после расчёта.

Статические M2/M3 оцениваются четырьмя цепями MH. Student-t предложение с df=12 построено по моде и Hessian; acceptance использует точный posterior. При необходимости длина цепей увеличивается до выполнения rank-normalized/folded split R-hat<1.01 и bulk/tail ESS≥400. Оптимизация проверена по аналитическому градиенту; Newton-уточнение устраняет precision loss BFGS у почти пуассоновского знаменателя.

## Оценка по L1 и временной информационный набор

Настройка: **июль–декабрь 2024**, 6 календарных месяцев. Выбирается q из 0.015/0.04/0.08 по среднему месячных средних scaled CRPS M4 (равный вес месяцев), затем основной прогноз из M1–M4/POOL по всем дневным forecast cases. Внешняя оценка: **январь 2025–сентябрь 2026**, 21 непересекающийся месяц. На каждом origin модели заново обучаются только на доступном прошлом.

Все модели оцениваются на одинаковых полных channel-days. Основные метрики: daily RMSE по predictive mean, CRPS, coverage и width 80/95%. CRPS нормируется на max(1, среднее соответствующего ряда в обучении) только для межсерийного выбора и агрегированной skill-оценки; обычные метрики тоже сохранены. Значения CRPS описывают эмпирические распределения по 2048 backtest-траекториям. Финальный прогноз содержит 30000 траекторий. Месячные интервалы — квантили сумм траекторий; месячные ошибки считаются лишь для полностью наблюдавшихся месяцев.

DM: парные средние потери по месячным блокам, Bartlett HAC lag=1 и Holm по четырём сравнениям с baseline отдельно для CRPS и squared loss. 21 блок даёт ограниченную точность асимптотических p-values. Неопределённость skill на рисунке: circular moving-block bootstrap с блоком 3 месяца, сохранением всех целей внутри месяца. Корреляция серий не превращается в фиктивно большой независимый размер выборки.

## Файлы и проверки

- `selection.json`: настройки, выбранные до test.
- `forecast_daily.csv`, `forecast_month.csv`: все модели, все основные цели; расширенные контексты для выбранной модели.
- `forecast_paths.npz`, `forecast_paths_possible.npz`: целые согласованные траектории, ключ `model__target`; оси draw × day × channel, порядок каналов `1TV,NTV,RUSSIA1,RUSSIA24`.
- `backtest_daily.csv.gz`, `backtest_monthly.csv`: individual forecast scores; `evaluation*.csv`: агрегации.
- `dm_tests.csv`, `q_validation.csv`: сравнения и настройка.
- `posterior_predictive_checks.csv`: mean, variance, zero-share, p95 реального последнего года и репликаций M1–M3. Это in-sample проверка адекватности, а не test-score.
- `calendar_effects.csv`: odds ratios точных дат B-компонента M3, не причинные эффекты.
- `particle_sensitivity.csv`: сравнение M4 при большем числе static draws и частиц; включает шум фильтров. Conditional SE финальных draws не исчерпывает его.
- `backtest_diagnostics.json`, `final_*_diagnostics.json`, `verification.json`, `manifest.json`: диагностики, проверка хронологии/траекторий/оценок и provenance.

Тесты сравнивают likelihood с SciPy, все аналитические градиенты с конечными разностями, CRPS с явной парной формулой; проверяют additive NB exposure, влияние пропущенных дней, праздничные признаки и поддержку генератора. Отдельный валидатор проверяет все 30000 траекторий каждого финального сценария, суммы, квантили, информационную границу и совпадение дат оценки.

## Ограничения

Контекстные метки остаются предварительными: независимая человеческая precision/recall не измерена. Расширенные неясные контексты — чувствительность, а не доказанная верхняя граница; основной ряд также не является доказанной нижней границей. ASR, длина транскриптов и неполнота архива влияют на измерение. Динамическая модель использует cut posterior и ограниченное окно состояний; дисперсии календарных приоров заданы. Между людьми остаётся зависимость сверх общего N. Непрохождение PPC и недостаточное покрытие не скрываются: они отражены в числах и пояснениях отчёта.

Историческая оценка ретроспективная, с одной исправленной версией архива и определением меток. Real-time vintages транскриптов/меток не сохранены: доступность этой точной версии в момент каждого origin не подтверждена.
